This is one machine/stationary scene, not certification of moving city performance or60 FPS on ordinary laptops.

Source findings to repair: RailwayOsm recomputes longest connected route in every Crossing mount and station-stop schedule in every per-frame trainState call. OsmCity mounts all tiles in a single frame, retains undisposed merged resources on streaming out, and quality switching inside the same tile does not update streaming radius because tile key alone gates refresh. Avatar uses fresh high-bevel meshes per person; some radius values exceed half the thin dimension. AdaptiveDpr `pixelated` explicitly requests pixelated canvas scaling when regressed. Full-store HUD subscriptions trigger at network snapshots; future separation must retain mission/chat responsiveness. Confirm performance effect with comparable samples, not speculative FPS claims.
